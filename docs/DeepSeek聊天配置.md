# DeepSeek 聊天配置

入口：`/en/tools/ai-chat`、`/zh/tools/ai-chat`，也可从首页工具目录打开 AI Chat。

## 本地配置

在 `ai-tools-site/.env.local` 中添加以下服务端变量（该文件不提交）：

```dotenv
DEEPSEEK_API_KEY=在这里填写你的密钥
DEEPSEEK_MODEL=deepseek-flash
```

密钥从 DeepSeek 控制台获取，不要发到聊天窗口，不要使用 `NEXT_PUBLIC_` 前缀。设置后重启 `npm run dev`。API 地址固定为 `https://api.deepseek.com/chat/completions`，不接受浏览器传入密钥或模型。

## 游客免费聊天

游客每个浏览器每天可免费获得 20 次回复；登录账号另有每天 20 次，各设备共享账号额度。统一在 UTC 零点恢复，页面显示本地恢复时间。额度通过签名 Cookie 和 Supabase 持久化；游客用完后弹出注册/登录提示，账号用完后等待次日恢复。

在 Supabase SQL Editor 中运行 [每日额度迁移](../ai-tools-site/supabase/migrations/202611200002_chat_daily_quota.sql)。该迁移新增表和 RPC，已运行旧版 `202611200001_chat_trials.sql` 的项目也可以升级；原数据保留，首次切换到每日账本时获得新的当日额度。新迁移可独立执行，只执行一次；使用迁移工具时按文件顺序执行。配置以下服务端变量：

```dotenv
SUPABASE_SERVICE_ROLE_KEY=Supabase service_role 密钥
CHAT_COOKIE_SECRET=至少32字符的随机私密值
```

日志不应包含这两个密钥。`CHAT_COOKIE_SECRET` 为空时兼容现有 `DRAWING_COOKIE_SECRET`；签名值至少 32 字符，所有实例保持一致。旧的 `CHAT_ALLOW_ANONYMOUS` 开关已不再使用。

如果暂时没有迁移数据库，可在本地 `ai-tools-site/.env.local` 中设置 `CHAT_QUOTA_STORE=memory`，重启 `npm run dev` 后测试完整交互。此模式仅限 development，进程内保存每日额度，重启后清空；不代表持久化数据库已配置。生产构建忽略该选项并强制使用 Supabase。DeepSeek API 调用仍真实计费，自动化测试则不会调用真实服务。

请求先校验、再原子预扣，完整回复（含达到输出长度上限）扣 1 次；失败或取消退回原日期额度。异常退出留下的预占在 3 分钟后由下一次查询/预扣回收。重复结算不会重复退款。数据库不可用时停止调用模型，避免绕过额度。

数据库还限制同一网络每分钟最多 15 次预占（包含失败尝试），减少更换游客 Cookie 绕过频率限制的问题。数据库只保存地址的 HMAC，共享网络共用此限制。Vercel 使用平台提供的 `x-vercel-forwarded-for`，其他部署需让可信代理覆盖 `x-forwarded-for`，不能信任客户端传入的地址。Cookie 可以删除，此机制不是严格的真人唯一识别，也不是全站费用硬上限。

额度账本持续增长，可定期清理已结算的历史预占和过期日桶（先删预占再删日桶，保留退款观察期），以及长期不活跃的网络限流记录。

2026-10-27 按官方文档默认使用 `deepseek-flash`，关闭思考模式，以优先保证普通聊天响应速度；也可配置当前账户可用的模型名。参考：[API 文档](https://api-docs.deepseek.com/api/create-chat-completion/)。

账户验证复用现有 Supabase，相关环境变量及回调设置见 [Supabase登录配置](./Supabase登录配置.md)。用户发送消息时如果未登录，会看到登录入口；登录在新标签页完成后回到聊天页重试，不用丢弃问题。原登录/账户页目前为中文。

## Vercel

在对应项目的 Environment Variables 中添加 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL`、`SUPABASE_SERVICE_ROLE_KEY`、`CHAT_COOKIE_SECRET`，应用每日额度迁移，确认 Supabase 配置及 `NEXT_PUBLIC_SITE_URL` 是正式域名，然后重新部署。服务端函数需要支持流式响应及至少 90 秒运行时间（路由 `maxDuration=120`，实际额度受平台套餐限制）。本站未在此任务自动部署。

## 当前能力与限制

- 中英文界面、连续上下文、流式回复、停止生成、失败重试、复制回复、新建对话。
- 输出为纯文本，不渲染 HTML；不支持附件、联网搜索或多模型选择。
- 对话仅保存在当前标签页内存，不写入数据库或 localStorage。刷新、切换语言或离开后不保留；清空有确认。
- 生成时会将当前对话上下文发送至 DeepSeek。不代表服务商不记录请求；请按服务商条款处理敏感信息。本站代码不记录消息或密钥。
- 使用 Supabase `getUser` 验证登录身份，未登录使用签名游客 Cookie。请求需同源；身份与网络限流并用，不自动重试付费请求。
- 请求体最多 160 KiB；最多 31 条消息，单条最多 8,000 字符，总上下文最多 24,000 字符；最多生成 4,096 tokens；90 秒后中止。
- 达到长度上限、新会话、重试与保留部分回复均提供明确操作；重试会重新调用 API 并可能计费。超出消息长度的回答可复制，但需要新建对话。
- 每日额度和网络限流存于数据库，多实例共享；目前没有付费购买额度功能。
- 目录暂标为“内测”，不是“已上线”。真实认证与模型调用验收后再更新状态。

## 验收步骤

1. 没有配置密钥时显示界面预览提示，不产生生成请求。
2. 应用每日额度迁移，配置服务端变量并重启；游客显示 20 次并可直接聊天；用完弹出注册提示。
3. 登录后回到原标签页，确认显示账号额度；发送短问题，确认回复逐步出现且成功扣 1 次。账号用完提示次日恢复。
4. 提问引用上一轮内容，确认上下文有效。
5. 测试停止、重试、复制和清空；手机布局不横向溢出。
6. 核对控制台用量及余额；不要将真实回答测试与离线模拟测试混淆。

自动测试使用模拟上游响应，不会消耗 DeepSeek 余额，也不能证明真实密钥、余额或线上服务已可用。

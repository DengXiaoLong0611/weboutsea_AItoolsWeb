# 手绘生成额度

按已讨论的方案：游客成功生成一次；登录后再生成一次；账户累计免费两次，之后要求购买。直接登录的新账户有两次免费额度。登录、刷新、重启和跨设备不会重置账户额度。结果可立即查看和下载，不在生成后拦截。

## 实现选择

前端存储容易重置；现有本地 JSON 账本不能覆盖 Vercel 多实例。采用现有 Supabase 的 Postgres 事务保存额度和预占记录。匿名 Cookie 用服务端 HMAC 签名，首次关联账户时转入已使用次数，只关联一次。匿名额度仍可能通过清理 Cookie 绕过，不能承诺防止所有滥用；增加全站每日匿名调用上限，暂不信任来源未经校验的 IP 请求头。

服务端验证用户身份，数据库函数仅允许 service_role 调用；普通用户不能改额度。生成前预占，成功确认，明确失败退还；同一访客或账户仅允许一个在途请求。进程中断留下的预占保守保留，五分钟后允许后续请求，避免未知上游结果导致重复免费调用。

## 验收与部署

覆盖匿名额度、账户额度、失败退还、并发拦截、登录返回路径和页面交互。数据库脚本需在 Supabase 执行；服务端设置 SUPABASE_SERVICE_ROLE_KEY 与 DRAWING_COOKIE_SECRET，绝不暴露到客户端。没有配置时返回 503，禁止退回不可靠的本地免费额度。

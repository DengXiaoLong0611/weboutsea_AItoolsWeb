# LangGraph 双语学习站设计

## 意图

在现有 AI 工具站下增加一个面向英文开发者的 LangGraph 教程站，同时保留中文读者直接阅读上游仓库原文的入口。学习站与 AI 工具站使用同一域名，便于从工具目录进入，并为后续搜索获客与广告变现打基础。

## 用户与目标

- 英文读者可从基础开始阅读 LangGraph 教程，默认进入英文页面。
- 中文读者可按原仓库内容阅读，不把中文原文改写成另一套课程。
- 两种语言共享一致的章节组织、代码示例、文档导航和搜索体验。
- 工具目录提供清晰入口；学习内容提供来源、作者和许可证说明。
- Vercel 继续使用现有 AI 工具站项目与同一个域名。

## 范围

- 根据克隆仓库中可读取的 24 篇 Markdown 教程，覆盖 module-0 至 module-4。
- 上游 `module-0/0.3-补充-LangChain-快速介绍.md` 含 NUL 与非 UTF-8 二进制字节，无法忠实渲染或翻译；保留于来源快照，并在上游修复前排除出中英文学习页。
- module-5 与 module-6 当前只有 Jupyter Notebook，没有 Markdown 教程；首版不把 Notebook 自动转换成新章节。
- 英文版逐章翻译 Markdown 正文和面向读者的说明；代码、API 标识符、文件名、命令及其语义保持准确。
- 中文版直接呈现仓库中的中文 Markdown 与首页内容。
- 增加英语默认、中文切换、章节导航、本地文档搜索、章节前后导航、来源及许可证信息。
- 在现有工具目录增加双语入口。
- 为未来广告位保留内容页布局空间；本次不接入广告网络、广告代码或发布者账户。

## 不在范围内

- 不把教程重写为新的 LangGraph 课程，也不更改上游中文正文。
- 不执行 Notebook、不提供浏览器内 Python 运行环境。
- 不建设用户账号、支付、课程进度同步或评论系统。
- 不在未审核上游技术内容的情况下声称教程与当前 LangGraph 最新版本完全一致。
- 不修改 AI 工具站已有的其他未提交内容。

## 上游依据与内容约束

- 来源：`https://github.com/memristors/langgraph-lightning`
- 克隆到的 HEAD：`ffb7345b963dd48a57f313aa07f3b4d076d8dbb4`，提交日期 2025-10-12。
- 仓库含 MIT `LICENSE`，但 README 同时注明内容版权归作者。页面保留许可证、作者与来源链接，并说明英文页为译文。
- VitePress 上游配置中的 `base`、GitHub 编辑地址和部分导航仍指向原作者仓库；接入时须更新站内部署路径及编辑链接，同时保留原作者主页和上游项目出处。
- 文章内容可能晚于其提交日期继续变化；本次固定到上述提交，页面注明版本来源，不暗示已完成最新 API 审查。

## 路由与语言

- `/learn/langgraph/`：英文首页，也是默认语言入口。
- `/learn/langgraph/zh/`：中文首页。
- 两种语言各自拥有对应模块和章节 URL，语言切换保持当前章节位置；如果译文缺失，退回对应语言首页。
- 设置匹配的 `lang`、canonical 与 `hreflang` 元数据；搜索引擎可以分别索引英中章节。

## 接入方式

### 选项 A：VitePress 静态输出挂载到现有 Next.js/Vercel 项目（选定）

在 AI 工具站仓库中保存上游内容快照与双语 VitePress 配置。Next.js 构建前生成 VitePress 静态站点到同域公开目录，通过显式重写处理首页、章节和静态资源。工具目录只负责入口，文档由 VitePress 渲染。

- 优点：保留上游文档站的 Markdown 工作流、代码高亮、搜索和章节导航；用户只访问一个域名、一套 Vercel 部署。
- 代价：构建顺序、静态路径和 Next.js rewrites 必须验证；内容快照和英文译文会增加仓库体积。

### 选项 B：独立 Vercel 学习站，再由工具目录跳转

完整保留 VitePress 独立项目与部署，AI 工具站添加外链。

- 优点：隔离清楚，VitePress 部署简单。
- 代价：会产生独立域名或部署地址，不满足用户选择的同域 `/learn/langgraph/`。

### 选项 C：把所有 Markdown 迁移到 Next.js 页面

用 Next.js 内容组件重新实现文档站。

- 优点：与主站路由、组件和主题统一。
- 代价：需要另造 Markdown 渲染、文档搜索、代码高亮和文档导航，重复实现上游已有能力，且更容易造成内容结构漂移。

采用选项 A，原因是用户已选择同域路径，而上游已经使用 VitePress，静态输出最接近原站且不需要重写教程。

## 视觉与交互

- 文档阅读页沿用 VitePress 的技术手册形态：章节侧栏、正文、页内目录、代码高亮、浅色/深色主题和响应式移动导航。
- 英文为默认语言，导航和按钮英文；中文路由保持中文界面。
- 首页呈现真实课程范围与学习顺序，不添加未核实的学习时长、课程效果或“官方课程”背书。
- 搜索限定当前语言，结果链接进入对应语言章节。
- 不制作虚假的在线代码执行控件或广告素材。

## 内容转换规则

- 中文版保留上游 Markdown 正文、标题、代码与示例的原始顺序。只为双语导航、来源说明和构建需要添加外围配置。
- 英文版翻译面向读者的中文段落、标题和注释；保留 LangGraph、LangChain、Python API 名称、代码、命令、文件路径和原有链接目标。链接路径需要通过构建检查确认。
- 译文应显式标注为非上游作者发布的翻译，并链接到对应中文原文和上游 GitHub 文件。
- 保留上游版权声明与 MIT 许可证文件。

## 影响的项目区域

- 上游内容快照与 `LICENSE`，放入 AI 工具站仓库内的独立 LangGraph 内容目录。
- VitePress 配置与英文译文目录。
- `ai-tools-site/package.json` 及锁文件：增加 VitePress 构建依赖/脚本，并在 Next 构建前生成静态文档。
- `ai-tools-site/next.config.ts`：处理 `/learn/langgraph` 静态首页和章节路由。
- 工具目录双语文案与入口。
- README、部署说明和来源说明。

## 验收

- VitePress 能生成英中首页、25 篇中文教程和对应英文页面。
- Next.js/Vercel 的同域路径可直接打开英文首页、中文首页、深层章节、搜索索引及静态资源。
- 语言切换保持章节位置；目录层级、相邻章节和锚点链接正常。
- 英文默认、中文切换、移动导航、搜索及代码高亮在桌面和手机尺寸下可用。
- 版权、许可证、上游链接、译文说明和固定提交信息清楚可见。
- 工具目录入口双语可达；现有其它工具、认证及未提交改动不受影响。
- 内容不出现误称“官方 LangGraph 课程”或未经核实的最新版本承诺。

## 实现者可自行决定

- VitePress 输出目录与 Next.js rewrite 的具体写法，以本地生产构建和深层 URL 实测为准。
- 章节 URL 的 slug 规则；尽量使用可读 ASCII slug，保持英中同章互换映射稳定。
- 英文译文的术语表和翻译批次；代码块和技术标识符不参与机器翻译。
- 未来接广告网络时再确认广告平台、账户审核和布局，不在本次加入外部广告脚本。

# 手绘免费额度与购买提示

## 用户流程

- 免登录成功生成 1 次，结果可直接查看和下载。
- 登录/注册后，累计免费生成 2 次，包含本浏览器已经使用的游客次数。直接登录的新账户可用 2 次。
- 第三次生成前返回购买提示（HTTP 402）。支付尚未开放，按钮不可付款，不会收款。
- 刷新或重启不会重置额度；同一账户跨浏览器、设备使用共享额度。
- 明确被模型拒绝的请求会退还次数。网络超时、丢失响应等结果不明的请求保留预占，管理员核实后处理，避免重复产生费用。

## 启用步骤

1. 打开 `ai-tools-site/supabase/migrations/202610300001_drawing_credits.sql`，复制全部内容，在对应 Supabase 项目的 **SQL Editor** 中运行。
2. 在 `ai-tools-site/.env.local` 配置以下服务端变量（线上填入部署平台环境变量）：

   ```dotenv
   SUPABASE_SERVICE_ROLE_KEY=你的legacy_service_role_JWT_key
   DRAWING_COOKIE_SECRET=至少32字符的随机私密值
   ```

   `SUPABASE_SERVICE_ROLE_KEY` 是项目 API Keys 中的 legacy `service_role` JWT key，不能填浏览器使用的 publishable/anon key。它拥有高权限，**不要加 `NEXT_PUBLIC_` 前缀，不要写入网页、Git 或聊天**。

   本次已在本地 `.env.local` 生成 `DRAWING_COOKIE_SECRET`。生产实例必须使用同一个稳定随机值，不要每次部署重新生成；更换会使旧游客 Cookie 失效。

3. 保留现有公开 Supabase 配置与百炼配置，重启本地 `npm.cmd run dev`。线上环境变量更新后重新部署。
4. 打开 `/tools/hand-drawn-photo/`，应显示“免登录可体验 1 次”。打开 `/api/hand-drawn-photo` 应返回当前剩余次数。缺少密钥、迁移或数据库不可用时返回 503，禁止回退到本地账本继续生成。

## 数据与权限

- `drawing_accounts`：账户已用免费次数、付费剩余次数。
- `drawing_visitors`：签名 Cookie 对应的游客记录及首次关联账户。
- `drawing_reservations`：每次生成的预占、成功或退还记录。不保存照片或提示词。
- 三张表启用 RLS，浏览器角色不能读写；三个 RPC 仅允许 `service_role` 执行。用户 ID 来自服务端验证的登录会话，不能从前端指定。
- 每次生成在数据库事务内先扣减/预占，之后才调用模型；同一游客或账户的请求会互相排斥。
- 在途请求阻挡 5 分钟。进程中断的记录不会自动退还，因为模型可能已完成并收费；5 分钟后解除在途限制，但该次数继续计入已用额度。
- 全站每天最多 20 次匿名上游尝试，UTC 零点重置（北京时间 08:00）。失败也计入此保护上限；账户终身免费额度不每日重置。

Cookie 无法识别清除缓存、换浏览器后的同一个人。匿名额度不承诺每个自然人仅一次；每日全站上限用于限制这类损失。不使用未经代理验证的 IP 请求头限制同一网络下的不同用户。

旧 `.drawing-trials` 文件账本不再用于正式接口，旧游客试用记录不会自动导入新数据库；本次切换后使用新版本签名 Cookie。

## 故障核对

在 SQL Editor 查询超过 5 分钟仍未结算的请求：

```sql
select id, user_id, kind, created_at
from public.drawing_reservations
where state = 'pending' and created_at < now() - interval '5 minutes'
order by created_at;
```

结合百炼调用记录核实。确认模型已完成则执行：

```sql
select public.drawing_settle('对应预占UUID'::uuid, true);
```

确认未生成、可以退还则执行：

```sql
select public.drawing_settle('对应预占UUID'::uuid, false);
```

结算幂等，同一请求不会重复退还。不要直接删除 pending 行或修改计数，会破坏额度一致性。

## 验证与支付后续

`npm.cmd test` 覆盖签名、额度拒绝、明确失败退还、未知结果保留、界面和登录返回路径。`tests/drawing-credits.sql` 在临时 PostgreSQL 验证真实事务逻辑，**只能用于可丢弃测试库**，不要在已有账本的生产项目运行测试文件。

支付接入后，必须由服务端验证支付回调，再按唯一订单幂等增加 `paid_credits`。当前没有充值 API、自动入账或真实购买按钮；客户端不能增加额度。

已知次要限制：如果以后重新开启注册邮箱确认，邮件确认完成后仍进入账户页；找回密码也保持原有账户流程。当前关闭邮箱确认的登录/注册可直接返回手绘页，原照片页通过新标签页登录保留。

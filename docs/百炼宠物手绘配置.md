# 百炼宠物手绘配置

目前只接入阿里云百炼，不安装其他平台 SDK，也不建立多平台框架。同一平台换模型，只改模型 ID；以后换平台时再添加对应调用实现，不是仅替换密钥。

## 1. 填写配置

编辑 `ai-tools-site/.env.local`，保留原有 Supabase 和 OpenAI 配置，填写以下内容：

```dotenv
DASHSCOPE_API_KEY=你的百炼密钥
DASHSCOPE_BASE_URL=https://你的业务空间ID.cn-beijing.maas.aliyuncs.com/api/v1
DASHSCOPE_IMAGE_MODEL=qwen-image-2.1-pro
```

地址仅为北京业务空间格式示例，不能原样使用。“业务空间ID”不是 API Key。请在百炼控制台复制与密钥、地域对应的 API 地址，保留到 `/api/v1`，不加后面的模型接口路径。若控制台提供传统 DashScope 地址，也支持其官方 HTTPS `/api/v1` 地址。

以上变量仅供本机脚本或服务端读取，不能加 `NEXT_PUBLIC_`，不能写入 `public/`，不要在聊天发送密钥。`.env.local` 已被 Git 忽略。部署时在托管平台的服务端环境变量中填写相同配置。

默认模型 `qwen-image-2.1-pro` 取自百炼使用指南；可用性和价格以你的地域、账户控制台为准。切换到同系列模型只改 `DASHSCOPE_IMAGE_MODEL`；其他家服务的接口结构不同，需要新增实现，不能将其他家密钥填到这里。

## 2. 先预览，不扣费

要求 Node.js 22.13 或更新的 22.x／更高版本（项目使用原生 TypeScript 类型剥离功能）。

```bash
cd ai-tools-site
npm run pet-photo:test
```

默认加载 `.env.local`，检查本地输入图并显示三组任务：蜡笔原景、细腻彩铅、蜡笔留白。不会联网、不会生成图片或消耗额度，也不输出密钥或 Base64 图片。进程中已经设置的环境变量优先于文件。

## 3. 实际生成，会调用付费 API

先生成一张：

```bash
npm run pet-photo:test -- --run --style 1
```

一次生成三组：

```bash
npm run pet-photo:test -- --run
```

指定自己的照片与风格参考（相对 `ai-tools-site/`，也接受绝对路径）：

```bash
npm run pet-photo:test -- --run --style 1 --image "自己的原照.jpg" --reference "自己的画风参考.png"
```

默认原照为 `public/tools/pet-photo/assets/demo/蛋蛋原照-抱玩偶.jpg`，参考图为 `public/tools/pet-photo/example/3.png`。该参考截图只用于本地风格测试，不作为网站展示成品；正式展示用实际生成作品。人物与宠物合照仍需另用自己的合照验证。

每组请求一张，不自动重试，遇到失败就停止。输出保存在 `ai-tools-site/output/imagegen/宠物手绘-时间-随机编号/`，包含原照、纯手绘 PNG、每组提示词及请求 ID／用量记录。使用独立目录，不覆盖旧作品。实际费用以百炼账单为准。

图片生成成功但下载失败时，结果记录仍保存请求 ID；先在控制台找回生成图片，避免重新生成造成重复费用。官方返回的图片链接通常只有 24 小时有效期。

## 4. 代码位置和当前边界

- `ai-tools-site/src/lib/pet-photo/bailian.ts`：服务端配置校验、调用同步图片编辑 API、响应和错误处理。
- `ai-tools-site/scripts/test-pet-photo.mjs`：本地三组测试、读取图片和保存结果。
- `ai-tools-site/tests/bailian.test.mjs`：离线请求契约及错误处理测试。
- `ai-tools-site/.env.example`：可提交的空白配置模板。

使用 Node 原生 `fetch`，未新增 SDK 或生产依赖。本轮尚未将生成按钮接入宠物网页，也没有公开扣费 API。以后接网页时，由服务端调用 `editPetPhoto`，再加与网站登录、用量额度匹配的入口控制。前端不要直接请求百炼或读取密钥。

测试输出为纯手绘图，便于评估画风。右上角原照对比由后续网页排版完成，保留真正的原照而不让模型重画它。

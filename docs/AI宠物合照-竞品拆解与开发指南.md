### 我们的定价

| SKU | 对标订单 | Beside & Bloom | 低于对标 |
| --- | ---: | ---: | ---: |
| 一张 | $19 | $13 | 31.6% |
| 两张 | $29 | $20 | 31.0% |

三张套餐比两张多 $3。价格按 USD 一次性结算，顾客可以在预览后选择张数。试卖先量每组预览成本（包含不付费的访客）、三图完成率、预览到购买转化率及整套占比。若每张调用成本是 C、购买转化率是 R，仅预览分摊到每笔成交的成本约为 3C ÷ R，再扣除支付、存储、获客、退款等成本后判断定价。

## 2. 概念与模块连接

```text
AI 工具目录 → 合照页 → 浏览器压缩两张独立参考图
                         ↓
                    Next.js 服务端
              ↙          ↓           ↘
  Supabase 原子额度    百炼生成      访客签名 Cookie
                         ↓
              私有存储：带水印图 + 无水印图
                         ↓
        访客相册选择 → Stripe Checkout 托管收银台
                         ↓
         Stripe 签名通知或服务端查询确认金额与图片
                         ↓
           Supabase 权益记录 → 短期下载链接／打印
```

- **访客身份和注册。** 工具第一页由服务端给浏览器签发 HttpOnly Cookie，关联私有相册，与主站 Supabase Auth 各自独立。更换浏览器或清 Cookie 会失去访问。竞品做跨设备找回的思路是把邮箱关联到订单，再发短期、一次性私有链接。将来接邮箱时可以复用主站邮件基础设施或接事务邮件服务，验证邮箱后再绑定相册。当前没有发邮件、送礼和相似度免费重生成。
- **模型。** `catalog.ts` 定场景与提示词，`bailian.ts` 发送真人参考图、宠物参考图和生成指令。三张图按首选优先逐张生成，以便首张生成后立刻可见。Cap 限制日额度，同一相册限定一对参考图及每景一次；上游结果未知时不自动重发。
- **数据库和存储。** 数据库记录额度及已付权益，私有对象存储保存服务端压缩并写入水印的小图和无水印交付图。原始上传文件不写入我们的存储。长边 4096 像素由服务端按比例缩放，不代表模型原生 4K。正式对公众开放前需结合图像供应商条款制定留存、删除和客服流程。
- **支付。** Checkout 金额由服务端按 SKU 计算。Stripe 托管收银台输入卡信息，付款完成后经签名 webhook 或返回页面的 Stripe 服务端回查写入权益。用户返回时不依赖会话 URL 的参数决定解锁，可以拿到数据库中的已购记录。正式收款前需要确认商户结算、退款、拒付、税务和区域规则。该版未接入退款后的自动撤权。
- **交付与实体。** 已付用户可下载无水印 JPEG，或添加题字后打印／保存为 PDF。配置咨询邮箱可提供装框照片、实体相册、马克杯、毛毯的询价入口，由顾客主动寄信。目前实体是人工询价，不会自动收费、下单、制作或发货。接实体供应商时需要新的 SKU、商品样图、收货地址、订单与运单状态，再把付款事件转成履约单。

## 3. 如何配置和体验

1. 在现有 Supabase 项目的 SQL Editor 运行 `ai-tools-site/supabase/migrations/202611220001_pet_portraits.sql`。确认 `pet-portraits` 存储桶为 Private。
2. 在 `ai-tools-site/.env.local` 或部署环境配置 `DASHSCOPE_API_KEY`、`DASHSCOPE_BASE_URL`、`DASHSCOPE_IMAGE_MODEL`、`NEXT_PUBLIC_SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`。用现有 `DRAWING_COOKIE_SECRET` 或专用 `PET_PORTRAIT_COOKIE_SECRET`（至少 32 字符）。保留密钥在服务端，Git 只提交 `.env.example`。
3. 试用生成时设 `PET_PORTRAIT_ENABLED=true`，默认全站每天最多 30 张，使用 `PET_PORTRAIT_DAILY_LIMIT` 调整。日界线按 UTC。先只做预览也可，页面会显示支付未开放。
4. 测试付款时配置 Stripe **测试模式** `STRIPE_SECRET_KEY` 和正确的 `NEXT_PUBLIC_SITE_URL`。把 Stripe 事件 `checkout.session.completed` 送到 `/api/pet-portrait/webhook`，把该事件目的地签名密钥放在 `STRIPE_PORTRAIT_WEBHOOK_SECRET`。本地可用 Stripe CLI 转发事件，部署可直接添加 HTTPS 事件目的地。
5. 用项目指定的 Node 版本进入 `ai-tools-site`，运行 `npm ci` 和 `npm run dev`。从首页「AI 宠物合照」进入，或直接访问 `/zh/tools/pet-portrait`。英文是 `/en/tools/pet-portrait`，西语和法语可由工具内切换。后两种语言覆盖这个工具，目录保持站点已有的中英文。
6. 测试用正常浏览器上传一张人像和一张宠物照，等三张水印图就绪。先用隐私窗口核对另一访客读不到预览和高清图。然后用 Stripe 官方测试卡完成 $13、$20 或 $23 的测试订单，核对同一浏览器刷新仍保留购买，且其他图仍不能下载。最后试打印、保存 PDF 和客服询价。测试订单清除浏览器 Cookie 前，可保留会话以便复查。

## 4. 接着怎么开发

| 改什么 | 从哪里入手 |
| --- | --- |
| 首屏、等待动画、图片选择、打印操作 | `ai-tools-site/src/components/pet-portrait.tsx` 与同名 CSS |
| 增加工具语言 | `src/lib/pet-portrait/copy.ts`、组件语言选项和页面语言链接，翻译等待及失败文案 |
| 改场景与肖像表现 | `src/lib/pet-portrait/catalog.ts` 及额度迁移里的场景约束，固定参考图对照测试人脸、宠物毛色和自然互动 |
| 改价格 | `src/lib/pet-portrait/catalog.ts` 的 `priceInCents`；它同时用于页面展示和收银台 |
| 查看请求与交付权限 | `src/app/api/pet-portrait/route.ts`；Webhook 在同目录下 `webhook/route.ts`，后端共用 `src/lib/pet-portrait/server.ts` |
| 接邮箱找回 | 设计短期凭证、验证邮箱才发链接、限流及防枚举，将手机号、照片与公开访问隔离 |
| 接实体履约 | 先用已付电子肖像开展人工询价，再确定印厂、可配送地区、成本和物流 API，最后独立上线实体商品结账 |

开发验证顺序：先跑类型检查、ESLint、单测和生产构建，再在独立测试环境完成三图及 Stripe 测试支付，之后才切换商户正式密钥。

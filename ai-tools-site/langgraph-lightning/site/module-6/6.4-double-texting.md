## Why concurrent input matters

A user may submit another message while the first run is active. Set multitask_strategy on the new run to define what happens on that thread. Tests need an actually running first request; otherwise an apparently successful second request proves little about concurrency.

## Reject or enqueue

reject refuses the new run while the thread is busy; the example catches an HTTPStatusError. enqueue preserves both requests and schedules the second after the first. In a UI, explain rejection or show queued status so input does not appear lost.

## Interrupt or rollback

interrupt stops the current run but retains progress already saved; the old run can be inspected as interrupted. rollback removes the prior run and restores thread state before starting the replacement. Neither policy should be assumed to undo external side effects such as an email already sent or an independent store write.

### Cell 3

```python
import httpx
from langchain_core.messages import HumanMessage

# Create a thread
thread = await client.threads.create()

# Create to dos
user_input_1 = "Add a ToDo to follow-up with DI Repairs."
user_input_2 = "Add a ToDo to mount dresser to the wall."
config = {"configurable": {"user_id": "Test-Double-Texting"}}
graph_name = "task_maistro"

run = await client.runs.create(
    thread["thread_id"],
    graph_name,
    input={"messages": [HumanMessage(content=user_input_1)]},
    config=config,
)
try:
    await client.runs.create(
        thread["thread_id"],
        graph_name,
        input={"messages": [HumanMessage(content=user_input_2)]},
        config=config,
        multitask_strategy="reject",
    )
except httpx.HTTPStatusError as e:
    print("Failed to start concurrent run", e)
```

### Cell 4

```python
from langchain_core.messages import convert_to_messages

# Wait until the original run completes
await client.runs.join(thread["thread_id"], run["run_id"])

# Get the state of the thread
state = await client.threads.get_state(thread["thread_id"])
for m in convert_to_messages(state["values"]["messages"]):
    m.pretty_print()
```

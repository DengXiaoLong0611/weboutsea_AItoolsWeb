## 🎯 Core Concept

### What is LangGraph?

LangGraph is a framework for building stateful multi-step applications. It models the application as a Graph where:

- **Node**: function that performs specific operations
- **Edge**: Define the path of the execution process
- **State**: Data passed between nodes

### Basic structure of the graph

```
START → Node 1 → [条件判断] → Node 2 或 Node 3 → END
```

**Features:**
- **Process Control**: Control the execution order of nodes through edges
- **State Management**: Each node can read and update status
- **Dynamic Routing**: Conditional edges dynamically select the next node based on status

### 2. Define state (State)

State is the **core data structure** of LangGraph and runs throughout the entire graph execution process.

```python
from typing_extensions import TypedDict

class State(TypedDict):
    graph_state: str
```

#### Python knowledge points: TypedDict

`TypedDict` is a type hint tool introduced in Python 3.8+, which is used to define the structure of the dictionary:

```python
# 传统字典 - 无类型提示
state = {"graph_state": "Hello"}

# TypedDict - 有类型提示
class State(TypedDict):
    graph_state: str  # 明确指定字段类型

state: State = {"graph_state": "Hello"}
```

**Advantages:**
1. **IDE support**: auto-completion and type checking
2. **Document Function**: Clearly display the data structure
3. **Error Prevention**: Static type checking finds potential errors

**Role in LangGraph:**
- `State` defines the data structure shared by all nodes in the graph
- Each node can access and modify fields in `State`
- Provides type-safe state management

### 3. Define nodes (Nodes)

Nodes are **Python functions** that perform specific operations.

```python
def node_1(state):
    print("---Node 1---")
    return {"graph_state": state['graph_state'] + " I am"}

def node_2(state):
    print("---Node 2---")
    return {"graph_state": state['graph_state'] + " happy!"}

def node_3(state):
    print("---Node 3---")
    return {"graph_state": state['graph_state'] + " sad!"}
```

#### Core features of node

**1. Input parameters**
```python
def node_1(state):
    #         ^^^^^
    #         必须接收 state 参数
```
- The first parameter is the current state (`State` type)
- The status field can be accessed via `state['graph_state']`

**2. Return value**
```python
return {"graph_state": state['graph_state'] + " I am"}
#      ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
#      返回一个字典，更新状态中的字段
```
- The returned dictionary will have **updated** status
- Default behavior: **overwrite** the original value (not merge)

**3. Status update mechanism**

```python
# 执行前：state = {"graph_state": "Hi, this is Lance."}
node_1(state)
# 执行后：state = {"graph_state": "Hi, this is Lance. I am"}
```

**Important**: The returned value will **completely replace** the original value of the corresponding field, unless a Reducer is used (explained in subsequent courses).

### 4. Define edges (Edges)

Edges define the connection relationships between nodes and are divided into two types:

#### Normal Edge

```python
builder.add_edge(START, "node_1")
```
- **Fixed routing**: always flows from the starting point to the ending point
- **Unconditional Execution**: This path will be taken every time

#### Conditional Edge

```python
import random
from typing import Literal

def decide_mood(state) -> Literal["node_2", "node_3"]:
    # 从状态中获取数据（这里未使用，仅作示例）
    user_input = state['graph_state']

    # 50/50 随机选择
    if random.random() < 0.5:
        return "node_2"  # 50% 概率返回 Node 2

    return "node_3"      # 50% 概率返回 Node 3
```

#### Python knowledge points: Literal type

`Literal` is an advanced type hint for Python 3.8+, used to limit the possible values ​​of the return value:

```python
from typing import Literal

def decide_mood(state) -> Literal["node_2", "node_3"]:
    #                     ^^^^^^^^^^^^^^^^^^^^^^^^^^^
    #                     返回值只能是 "node_2" 或 "node_3"
    return "node_2"  # ✅ 合法
    # return "node_4"  # ❌ 类型检查会报错
```

**Advantages:**
1. **Type safety**: IDE will check whether the return value is legal
2. **Autocomplete**: The editor will prompt available options
3. **Document Function**: Clearly display all possible paths

#### How conditional edges work

```python
# 条件函数的职责
def decide_mood(state) -> Literal["node_2", "node_3"]:
    # 1. 读取状态
    user_input = state['graph_state']

    # 2. 执行逻辑判断
    if some_condition:
        return "node_2"  # 路由到节点 2
    else:
        return "node_3"  # 路由到节点 3
```

**Execution process:**
1. Node 1 is executed
2. LangGraph calls `decide_mood(state)`
3. Select the next node based on the return value ("node_2" or "node_3")
4. Execute the selected node

### 5. Graph Construction

Now assemble all the components into the complete diagram.

```python
from IPython.display import Image, display
from langgraph.graph import StateGraph, START, END

# 1. 初始化图构建器
builder = StateGraph(State)

# 2. 添加节点
builder.add_node("node_1", node_1)
builder.add_node("node_2", node_2)
builder.add_node("node_3", node_3)

# 3. 添加边
builder.add_edge(START, "node_1")                    # 开始 → 节点1
builder.add_conditional_edges("node_1", decide_mood) # 节点1 → 条件判断
builder.add_edge("node_2", END)                      # 节点2 → 结束
builder.add_edge("node_3", END)                      # 节点3 → 结束

# 4. 编译图
graph = builder.compile()

# 5. 可视化
display(Image(graph.get_graph().draw_mermaid_png()))
```

#### Detailed explanation of LangGraph core API

**1.StateGraph**
```python
builder = StateGraph(State)
#                    ^^^^^
#                    传入状态类型
```
- Graph builder for adding nodes and edges
- Generic class, accepting `State` type parameters
- Ensure all nodes use the same state structure

**2. add_node**
```python
builder.add_node("node_1", node_1)
#                ^^^^^^^^  ^^^^^^
#                节点名称   节点函数
```
- Register nodes into the graph
- Node name used for edge connection (string form)
- Node functions are the actual executed logic

**3. add_edge**
```python
builder.add_edge(START, "node_1")
#                ^^^^^  ^^^^^^^^
#                起点    终点
```
- Add fixed routing edges
- `START` and `END` are special nodes (explained later)

**4. add_conditional_edges**
```python
builder.add_conditional_edges("node_1", decide_mood)
#                             ^^^^^^^^  ^^^^^^^^^^^
#                             起点节点   条件函数
```
- Add edges for conditional routing
- The conditional function returns the name of the next node
- Automatically route to the corresponding node based on the return value

**5. compile**
```python
graph = builder.compile()
```
- Convert builders into executable graphs
- Perform basic validation (e.g. check if edge connections are valid)
- Return `CompiledGraph` object, you can call `invoke` and other methods

#### Special nodes: START and END

**START node**
- Entry point of graph
- Receive user input
- Pass the input to the first node

```python
builder.add_edge(START, "node_1")
# 用户输入 → node_1
```

**END node**
- the exit point of the graph
- mark the end of execution
- Return to final state

```python
builder.add_edge("node_2", END)
# node_2 → 结束并返回结果
```


Generate a Mermaid diagram showing the structure of the diagram:
- Node: rectangular box
- Edge: Arrow connection
- Conditional edge: diamond judgment box

### 6. Graph Invocation

The graph implements LangChain's **Runnable protocol** and provides a unified execution interface.

```python
graph.invoke({"graph_state": "Hi, this is Lance."})
```

**Example output:**
```
---Node 1---
---Node 3---
{'graph_state': 'Hi, this is Lance. I am sad!'}
```

#### Detailed explanation of invoke method

**1. Input parameters**
```python
graph.invoke({"graph_state": "Hi, this is Lance."})
#            ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
#            初始状态（字典形式）
```
- Input must be a dictionary
- Field must match `State` definition
- Set the initial state of the graph

**2. Execution process**

```python
# 1. 初始状态
state = {"graph_state": "Hi, this is Lance."}

# 2. START → node_1
state = node_1(state)
# {"graph_state": "Hi, this is Lance. I am"}

# 3. 条件边判断
next_node = decide_mood(state)  # 返回 "node_3"

# 4. node_3 执行
state = node_3(state)
# {"graph_state": "Hi, this is Lance. I am sad!"}

# 5. END 节点
return state
```

**3. Return value**
```python
result = graph.invoke({"graph_state": "Hi, this is Lance."})
print(result)
# {'graph_state': 'Hi, this is Lance. I am sad!'}
```
- Returns the final state (dictionary form)
- Contains the latest values for all status fields

#### Synchronous execution features

```python
invoke() # 同步方法
```
- **Blocking Execution**: Wait for each node to complete before continuing
- **Sequential execution**: Execute in sequence according to the definition of edges
- **Final Return**: Return to the final state after all nodes are executed

**Comparing asynchronous methods (subsequent course):**
- `invoke()`: Sync, waiting for completion
- `ainvoke()`: asynchronous, non-blocking
- `stream()`: streaming, stepwise return

### LangGraph-specific concepts

#### 1. State

**Definition:**
```python
from typing_extensions import TypedDict
```

**Function:**

```python
def node_name(state):

    value = state['field_name']
```

**Features:**
- Must receive `state` parameter
- Return dictionary update status

**Normal side:**

```python
builder.add_edge("node_a", "node_b")
```

```python
def condition(state) -> Literal["node_b", "node_c"]:

builder.add_conditional_edges("node_a", condition)
```

## 💡 Best Practices

### 1. When to use simple diagrams?

✅ **Applicable scenarios:**
- Learn the basic concepts of LangGraph
- Simple process control (3-5 nodes)
- Simple tasks requiring conditional routing
- Prototype development and proof of concept

❌ **Not applicable scenarios:**
- Complex multi-step processes (consider subgraphs)
- Requires parallel execution (consider Map-Reduce)
- Requires looping and retrying (think loop graph)
- Complex state management (consider multi-state design)

### 2. State design principles

#### Principle 1: Keep state simple

```python
# ✅ 好的设计 - 只包含必需字段
class State(TypedDict):
    user_input: str
    result: str

# ❌ 不好的设计 - 过多字段
class State(TypedDict):
    user_input: str
    intermediate_1: str
    intermediate_2: str
    intermediate_3: str
    temp_value: str
    result: str
```

#### Principle 2: Use meaningful field names

```python
# ✅ 清晰的命名
class State(TypedDict):
    user_query: str
    search_results: list[str]
    final_answer: str

# ❌ 模糊的命名
class State(TypedDict):
    data: str
    result: list
    output: str
```

#### Principle 3: Appropriate field types

```python
class State(TypedDict):
    # 简单类型
    message: str
    count: int
    is_done: bool

    # 复杂类型
    items: list[str]
    metadata: dict[str, Any]

    # 自定义类型（后续课程）
    # response: ChatMessage
```

### 3. Node design skills

#### Tip 1: Single Responsibility

```python
# ✅ 每个节点做一件事
def fetch_data(state):
    data = api.fetch()
    return {"data": data}

def process_data(state):
    result = process(state["data"])
    return {"result": result}

# ❌ 节点做太多事情
def do_everything(state):
    data = api.fetch()
    result = process(data)
    final = format(result)
    return {"final": final}
```

#### Tip 2: Add a log

```python
def node_1(state):
    print(f"---Node 1 执行---")
    print(f"输入状态: {state}")

    result = process(state)

    print(f"输出状态: {result}")
    return result
```

#### Tip 3: Error handling

```python
def safe_node(state):
    try:
        result = risky_operation(state)
        return {"result": result, "error": None}
    except Exception as e:
        return {"result": None, "error": str(e)}
```

### 4. Design of conditional edges

#### Tip 1: Stateful Routing

```python
def route_by_state(state) -> Literal["node_a", "node_b"]:
    # 基于状态字段做决策
    if state["score"] > 0.8:
        return "node_a"
    return "node_b"
```

#### Tip 2: Multi-condition judgment

```python
def complex_routing(state) -> Literal["node_a", "node_b", "node_c"]:
    value = state["value"]

    if value < 10:
        return "node_a"
    elif value < 50:
        return "node_b"
    else:
        return "node_c"
```

#### Tip 3: Add a default route

```python
def safe_routing(state) -> Literal["node_a", "node_b", "error_node"]:
    try:
        if state["condition"]:
            return "node_a"
        return "node_b"
    except:
        return "error_node"  # 异常情况的默认路由
```

## 🔍 Frequently Asked Questions

### Q1: Why does the node return a dictionary instead of returning a value directly?

Because LangGraph needs to know which state field to update:

```python
# ✅ 正确 - 明确指定更新的字段
def node(state):
    return {"graph_state": "new_value"}

# ❌ 错误 - LangGraph 不知道如何更新状态
def node(state):
    return "new_value"
```

### Q2: Can a node not return any value?

Yes, but the status will not be updated:

```python
def node(state):
    print("This node only prints")
    # 不返回任何值，状态保持不变
```

Suitable for nodes that only perform side effects (such as logging, notifications).

### Q3: Does the return value of a conditional edge have to be of Literal type?

Not required, but highly recommended:

```python
# 推荐 ✅ - 类型安全
def decide(state) -> Literal["node_a", "node_b"]:
    return "node_a"

# 可行但不推荐 - 无类型检查
def decide(state):
    return "node_a"  # 可能拼写错误导致运行时错误
```

### Q4: Can variables be shared between nodes?

Not recommended. Data should be passed via state:

```python
# ❌ 不好的做法 - 全局变量
shared_data = []

def node_1(state):
    shared_data.append("data")
    return {}

# ✅ 好的做法 - 通过状态
class State(TypedDict):
    shared_data: list[str]

def node_1(state):
    return {"shared_data": state["shared_data"] + ["data"]}
```

### Q5: Can the START and END nodes be omitted?

Can't. They are required special nodes:

```python
# ❌ 错误 - 缺少 START
builder.add_edge("node_1", "node_2")

# ✅ 正确
builder.add_edge(START, "node_1")
builder.add_edge("node_2", END)
```

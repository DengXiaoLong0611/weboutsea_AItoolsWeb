# LangGraph Deployment Detailed interpretation 🚀

## 📚 Overview

This document explains LangGraph’s **deployment** process in detail. Deployment is a critical step in pushing the Agent we build from the local development environment to the production environment. With LangGraph Cloud and LangGraph Studio, we can easily test, monitor, and manage our AI applications.

## 🎯 Core Concept

### Why do we need to deploy?

In previous lessons, we have learned:
- ✅ Build Agent (act) with tools
- ✅ Processing tool output (observe)
- ✅ Let Agent perform reasoning (reason)
- ✅ Use memory to maintain state (persist state)

But these are all run in a local Jupyter Notebook. To make Agent truly serve users, we need to:
- 🌐 **Accessibility**: accessible to other apps via API
- 📊 **Observability**: Monitor running status and performance
- 🔄 **Scalability**: Support concurrent access by multiple users
- 🛡️ **Reliability**: error handling, retries, persistence

This is what deployment is all about!

### 1. LangGraph Library

**Role:** Core Python/JavaScript library for building Agent workflows

```python
from langgraph.graph import StateGraph, START, END

# 使用 LangGraph 定义图
graph = StateGraph(State)
graph.add_node("agent", call_model)
graph.add_edge(START, "agent")
graph.add_edge("agent", END)
app = graph.compile()
```

**Features:**
- Provide graph construction API
- Define status management
- Supports advanced functions such as conditional edges and loops

### 2. LangGraph API

**Function:** Package graph code into deployable services

**Core features:**
- 🔄 **Task Queue**: Manage asynchronous operations and handle concurrent requests
- 💾 **Persistence**: Save conversation history and status (across sessions)
- 🔌 **HTTP API**: Provides RESTful interface

**Why is it needed? **

There are limitations to running graph code directly:
```python
# 本地直接运行 - 只能单次执行
app = graph.compile()
result = app.invoke({"messages": [HumanMessage("Hello")]})
```

Using LangGraph API:
```python
# 通过 API - 支持流式、异步、多线程
async for chunk in client.runs.stream(
    thread_id="user-123",
    assistant_id="agent",
    input={"messages": [HumanMessage("Hello")]}
):
    print(chunk)
```

### 5. LangGraph SDK

**Role:** Python client library for programmatic interaction

```python

# 列出所有助手
```

#### 3. agent.py example

```python
from typing import Annotated
from typing_extensions import TypedDict
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool

# 定义工具
@tool
def multiply(a: int, b: int) -> int:
    """Multiply two numbers."""
    return a * b

# 定义状态
class State(TypedDict):
    messages: Annotated[list, add_messages]

# 定义节点
def call_model(state: State):
    llm = ChatOpenAI(model="gpt-4o")
    llm_with_tools = llm.bind_tools([multiply])
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

# 构建图
graph_builder = StateGraph(State)
graph_builder.add_node("agent", call_model)
graph_builder.add_edge(START, "agent")
graph_builder.add_edge("agent", END)
graph = graph_builder.compile()
```

### Code Example

#### 1. Connect to local server

```python
from langgraph_sdk import get_client
```

**Python knowledge points: async/await**

LangGraph SDK uses asynchronous programming:

```python
# ❌ 错误 - 同步调用会报错
assistants = client.assistants.search()

# ✅ 正确 - 异步调用
assistants = await client.assistants.search()
```

**Why use asynchronous? **
- Non-blocking I/O to improve concurrency performance
- Support streaming response
- Better handling of long-running tasks

**How ​​to use it in Jupyter? **
Jupyter Notebook supports top-level `await` by default:

```python
# 直接使用 await（仅在 Notebook 中）
result = await client.runs.stream(...)

# 在普通 Python 脚本中需要：
import asyncio
asyncio.run(main())
```

#### 2. Search for available assistants (picture)

```python
# 搜索所有已部署的图
assistants = await client.assistants.search()

# 查看第一个助手
print(assistants[0])
```

**Example output:**
```python
{
    'assistant_id': 'fe096781-5601-53d2-b2f6-0d3403f7e9ca',
    'graph_id': 'agent',
    'config': {},
    'metadata': {'created_by': 'system'},
```

**Field description:**
- `assistant_id`: unique identifier (UUID)
- `graph_id`: name of the graph (from `langgraph.json`)
- `config`: configuration options (such as model parameters)

#### 3. Create a conversation thread

```python
# 创建新线程用于跟踪状态
thread = await client.threads.create()

print(thread['thread_id'])
# 输出：'1ef6c123-4567-89ab-cdef-0123456789ab'
```

**LangGraph knowledge point: Thread (thread)**

Thread is the **state container** in LangGraph:

```
Thread = 独立的对话会话 = 独立的状态快照
```

**Why do you need Thread? **
-Support multi-user concurrency (one Thread per user)
- Persist conversation history (keep state across requests)
-Isolate different sessions (avoid state confusion)

**Example scenario:**
```python
# 用户 A 的对话
thread_a = await client.threads.create()
client.runs.stream(thread_a['thread_id'], "agent", input={"messages": [...]})

# 用户 B 的对话（完全独立）
thread_b = await client.threads.create()
client.runs.stream(thread_b['thread_id'], "agent", input={"messages": [...]})
```

#### 4. Run the graph and stream the output

```python
from langchain_core.messages import HumanMessage

# 输入消息
input = {"messages": [HumanMessage(content="Multiply 3 by 2.")]}

# 流式运行图
async for chunk in client.runs.stream(
    thread['thread_id'],     # 线程 ID
    "agent",                 # 图 ID
    input=input,             # 输入数据
    stream_mode="values",    # 流模式
):
    if chunk.data and chunk.event != "metadata":
        print(chunk.data['messages'][-1])
```

**Parameter details:**

| Parameters | Description | Example |
|------|------|------|
| `thread_id` | Thread identifier | `'1ef6c123-...'` |
| `assistant_id` | Assistant ID (picture name) | `'agent'` |
| `input` | Input status | `{"messages": [...]}` |
| `stream_mode` | Streaming mode | `"values"` / `"updates"` |

**LangGraph knowledge point: Stream Modes**

LangGraph supports multiple streaming modes:

1. **`stream_mode="values"`** - Complete state flow
   ```python
   # 每步后返回完整状态
   {'messages': [msg1]}
   {'messages': [msg1, msg2]}
   {'messages': [msg1, msg2, msg3]}
   ```

2. **`stream_mode="updates"`** - Incremental update stream
   ```python
   # 每步只返回新增的状态
   {'messages': [msg1]}
   {'messages': [msg2]}
   {'messages': [msg3]}
   ```

3. **`stream_mode="messages"`** - Message flow (messages only)
   ```python
   # 直接返回消息对象
   AIMessage(content="...")
   ToolMessage(content="...")
   ```

**Example of run output:**

```python
# 第 1 步：用户消息
{'content': 'Multiply 3 by 2.', 'type': 'human', 'id': 'cdbd7bd8-...'}

# 第 2 步：AI 调用工具
{'content': '', 'type': 'ai', 'tool_calls': [{'name': 'multiply', 'args': {'a': 3, 'b': 2}}]}

# 第 3 步：工具执行结果
{'content': '6', 'type': 'tool', 'name': 'multiply', 'tool_call_id': 'call_iIPry...'}

# 第 4 步：AI 最终响应
{'content': 'The result of multiplying 3 by 2 is 6.', 'type': 'ai'}
```

**Code analysis:**

```python
async for chunk in client.runs.stream(...):
    # chunk 是流式响应的片段

    if chunk.data and chunk.event != "metadata":
        # chunk.data：包含状态数据
        # chunk.event：事件类型（如 "values", "metadata"）

        print(chunk.data['messages'][-1])
        # 打印最新消息（列表最后一项）
```

## 🎓 Summary of core knowledge points

### LangGraph-specific concepts

#### 1. Deployment

**Definition:** The process of migrating a LangGraph application from a development environment to a production environment

**Key components:**
- **langgraph.json**: Configuration file, defining graph path and dependencies
- **LangGraph API**: Provides HTTP interface and task queue
- **Thread**: state container, supports multi-user sessions
- **Assistant**: Runtime instance of the graph

#### 2. Thread vs Assistant

| Concept | Function | Analogy | Persistence |
|------|------|------|-------|
| **Assistant** | Graph definition (code) | Program executable file | Yes |
| **Thread** | State instance (data) | The running process of the program | Yes |

```python
# 一个 Assistant（图）可以有多个 Thread（会话）
assistant_id = "agent"

thread1 = await client.threads.create()  # 用户 A 的会话
thread2 = await client.threads.create()  # 用户 B 的会话

# 同一个 Assistant，不同的 Thread
client.runs.stream(thread1['thread_id'], assistant_id, ...)
client.runs.stream(thread2['thread_id'], assistant_id, ...)
```

#### 3. Stream Modes comparison

```python
# 场景 1：需要完整状态（如 UI 渲染）
stream_mode="values"
# → {'messages': [msg1, msg2, msg3]}

# 场景 2：只关心新增数据（如增量更新）
stream_mode="updates"
# → {'messages': [msg3]}

# 场景 3：只处理消息（如聊天应用）
stream_mode="messages"
# → AIMessage(content="...")
```

#### 4. Local vs cloud deployment

| Features | Local development (`langgraph dev`) | Cloud deployment (LangGraph Cloud) |
|------|---------------------------|---------------------------|
| **Purpose** | Development and Testing | Production Environment |
| **URL** | `http://127.0.0.1:2024` | `https://xxx.langgraph.app` |
| **Environment Variables** | `.env` File | LangSmith UI Configuration |
| **Hot Reload** | ✅ Support | ❌ Redeploy required |
| **Persistence** | Memory (lost on restart) | Database (permanent) |
| **Monitoring** | Basic logs | Complete tracking and analysis |
| **Cost** | Free | Pay per usage |

### Python-specific knowledge points

#### 1. Asynchronous programming (async/await)

**Why use asynchronous? **

Synchronous call (blocking):
```python
# 调用 API → 等待响应 → 继续执行
result1 = call_api_1()  # 等待 2 秒
result2 = call_api_2()  # 等待 2 秒
# 总耗时：4 秒
```

Asynchronous call (non-blocking):
```python
# 同时发起多个请求，并发等待
result1 = await call_api_1()  # 异步等待 2 秒
result2 = await call_api_2()  # 异步等待 2 秒
# 总耗时：2 秒（并发执行）
```

**Basic syntax:**

```python
# 定义异步函数
async def fetch_data():
    result = await some_async_operation()
    return result

# 调用异步函数
# 方式 1：在 Jupyter Notebook 中
data = await fetch_data()

# 方式 2：在普通 Python 脚本中
import asyncio
data = asyncio.run(fetch_data())
```

**Applications in LangGraph SDK:**

```python
# ✅ 所有 SDK 方法都是异步的
await client.assistants.search()
await client.threads.create()
async for chunk in client.runs.stream(...):
    process(chunk)
```

#### 2. Asynchronous iterator (async for)

**Normal iterator:**
```python
# 同步迭代
for item in [1, 2, 3]:
    print(item)
```

**Asynchronous iterator:**
```python
# 异步迭代
async for chunk in async_generator():
    print(chunk)
```

**Usage in LangGraph:**

```python
# client.runs.stream() 返回异步生成器
async for chunk in client.runs.stream(thread_id, assistant_id, input=...):
    # 每次 yield 一个新的状态片段
    if chunk.data:
        print(chunk.data)
```

**Equivalent synchronization writing method (for understanding):**
```python
# 如果 stream() 是同步的，代码会是这样：
for chunk in client.runs.stream_sync(...):  # 假设有同步版本
    print(chunk.data)
```

### Q7: What is the practical difference between stream_mode="values" and "updates"?

**Example scenario:** Chat application showing Agent thought process

**Use "values":**
```python
async for chunk in client.runs.stream(thread_id, "agent", input=..., stream_mode="values"):
    # 每次获得完整状态
    all_messages = chunk.data['messages']

    # UI 需要每次重新渲染整个对话
    display_all_messages(all_messages)
```

**Use "updates":**
```python
async for chunk in client.runs.stream(thread_id, "agent", input=..., stream_mode="updates"):
    # 只获得新增消息
    new_messages = chunk.data['messages']

    # UI 只需要追加新消息
    append_messages(new_messages)
```

**Selection suggestions:**
- **"values"**: suitable for simple UI, fully updated every time
- **"updates"**: suitable for complex UI that requires incremental updates (more efficient)

## 📊 Comparison summary of local vs. cloud

| Dimensions | Local development | Cloud deployment |
|------|---------|---------|
| **Start Command** | `langgraph dev` | By LangSmith UI |
| **URL** | `http://127.0.0.1:2024` | `https://xxx.langgraph.app` |
| **Environment Variables** | `.env` File | LangSmith UI Configuration |

| **State persistence** | Memory (lost on restart) | Database (permanent) |
| **Applicable scenarios** | Development, testing, debugging | Production, multi-user, long-term operation |
| **Cost** | Free (local resources only) | Pay per usage |

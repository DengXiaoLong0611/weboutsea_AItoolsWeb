# Detailed interpretation of LangGraph research assistant case

## 📋 Case Overview

This case shows how to use LangGraph to build an **intelligent research assistant system** that can:

1. Automatically generate multiple professional analysts based on research topics
2. Each analyst conducts in-depth interviews on specific subtopics
3. Perform multiple interviews in parallel to improve efficiency
4. Finally integrate all interviews into a complete research report

### Core technical points

- **Human-in-the-Loop** (Human-in-the-Loop): Users can review and modify the generated analyst team
- **Structured Output**: Use Pydantic models to ensure consistent data format
- **Sub-picture nesting**: The interview process is embedded in the main picture as an independent sub-picture
- **Parallel Execution** (Map-Reduce): Run multiple interviews simultaneously using the `Send()` API
- **Checkpoint mechanism**: supports interrupting and resuming the execution process

### Part 2: Generating Analysts (First Figure)

#### Status definition

```python
class GenerateAnalystsState(TypedDict):
    topic: str                    # 研究主题
    max_analysts: int             # 最大分析师数量
    human_analyst_feedback: str   # 用户反馈
    analysts: List[Analyst]       # 生成的分析师列表
```

**Key Concept**: State is the core concept in LangGraph. It is like a "shared memory" that transfers data between nodes.

---

#### Node function

**1. create_analysts node**

```python
def create_analysts(state: GenerateAnalystsState):
    # 使用 structured_output 确保 LLM 返回符合 Perspectives 格式的数据
    structured_llm = llm.with_structured_output(Perspectives)

    # 构建系统提示词
    system_message = analyst_instructions.format(
        topic=topic,
        human_analyst_feedback=human_analyst_feedback,
        max_analysts=max_analysts
    )

    # 调用 LLM 生成分析师
    analysts = structured_llm.invoke([SystemMessage(...)])

    return {"analysts": analysts.analysts}
```

**Technical Highlights**:
- `with_structured_output()` forces LLM to return JSON conforming to the `Perspectives` model
- Prompt words include topics, user feedback and quantity limits
- The returned dictionary will update the `analysts` field in the status

---

**2. human_feedback node**

```python
def human_feedback(state: GenerateAnalystsState):
    pass  # 空操作节点
```

**Why do we need empty nodes? **
- This is an "interrupt point"
- When execution reaches this point, the graph will pause and wait for user input.
- Users can modify the status through `graph.update_state()`

---

**3. should_continue conditional edge**

```python
def should_continue(state: GenerateAnalystsState):
    human_analyst_feedback = state.get('human_analyst_feedback', None)

    if human_analyst_feedback:
        return "create_analysts"  # 有反馈，重新生成

    return END  # 无反馈，结束
```

**Logic explanation**:
- Check if there is `human_analyst_feedback` in the status
- If there is → go back to `create_analysts` and regenerate
- If not → end this phase

---

#### Graph construction

```python
builder = StateGraph(GenerateAnalystsState)
builder.add_node("create_analysts", create_analysts)
builder.add_node("human_feedback", human_feedback)

# 边的连接
builder.add_edge(START, "create_analysts")
builder.add_edge("create_analysts", "human_feedback")
builder.add_conditional_edges("human_feedback", should_continue,
                             ["create_analysts", END])

# 编译图
graph = builder.compile(
    interrupt_before=['human_feedback'],  # 在此节点前中断
    checkpointer=memory                   # 使用内存保存状态
)
```

**Key Mechanism**:
- `interrupt_before` causes the graph to pause before `human_feedback`
- `checkpointer` saves execution status and supports recovery
- `conditional_edges` determines the next step based on the function return value

### Part Three: Executive Interview (Sub-Picture)

#### Interview status

```python
class InterviewState(MessagesState):
    max_num_turns: int      # 最大对话轮数
    context: Annotated[list, operator.add]  # 检索到的文档
    analyst: Analyst        # 当前分析师
    interview: str          # 访谈记录
    sections: list          # 生成的章节
```

**NOTE**: `context: Annotated[list, operator.add]`
- `Annotated` specifies how to merge states
- `operator.add` means the new context will be appended to the existing list
- This way multiple search results can be accumulated

---

#### Core node

**1. generate_question - Analyst question**

```python
def generate_question(state: InterviewState):
    analyst = state["analyst"]
    messages = state["messages"]

    # 构建系统提示
    system_message = question_instructions.format(goals=analyst.persona)

    # LLM 根据分析师的角色生成问题
    question = llm.invoke([SystemMessage(content=system_message)] + messages)

    return {"messages": [question]}
```

**Workflow**:
1. Get the analyst’s persona
2. Combine the conversation history to generate the next question
3. The question will be appended to the message list

---

**2. search_web and search_wikipedia - Parallel Search**

```python
def search_web(state: InterviewState):
    # 将对话转换为搜索查询
    structured_llm = llm.with_structured_output(SearchQuery)
    search_query = structured_llm.invoke([search_instructions] + state['messages'])

    # 使用 Tavily 搜索
    search_docs = tavily_search.invoke(search_query.search_query)

    # 格式化结果
    formatted_search_docs = "\n\n---\n\n".join([
        f'<Document href="{doc["url"]}"/>\n{doc["content"]}\n</Document>'
        for doc in search_docs
    ])

    return {"context": [formatted_search_docs]}
```

**Technical Details**:
- First use LLM to refine conversations into search queries
- Call external search tools (Tavily/Wikipedia)
- Formatted into documents with source annotations
-The returned context will be automatically merged into the state

**3. generate_answer - expert answer**

```python
def generate_answer(state: InterviewState):
    analyst = state["analyst"]
    messages = state["messages"]
    context = state["context"]  # 检索到的所有文档

    # 构建包含上下文的提示
    system_message = answer_instructions.format(
        goals=analyst.persona,
        context=context
    )

    # 生成答案
    answer = llm.invoke([SystemMessage(content=system_message)] + messages)
    answer.name = "expert"  # 标记消息来源

    return {"messages": [answer]}
```

**RAG Mode**:
- Use the retrieved context as a source of knowledge
- LLM answers questions based on these documents
- Include citations in the answer (e.g. [1], [2])

**4. route_messages - routing logic**

```python
def route_messages(state: InterviewState, name: str = "expert"):
    messages = state["messages"]
    max_num_turns = state.get('max_num_turns', 2)

    # 统计专家回答的次数
    num_responses = len([
        m for m in messages
        if isinstance(m, AIMessage) and m.name == name
    ])

    # 达到上限则保存访谈
    if num_responses >= max_num_turns:
        return 'save_interview'

    # 检查是否包含结束语
    last_question = messages[-2]
    if "Thank you so much for your help" in last_question.content:
        return 'save_interview'

    return "ask_question"  # 继续提问
```

**Control logic**:
- Limit the number of interview rounds to prevent infinite loops
- Detection end signal (thank you)
- Decide whether to continue asking questions or end the interview

### Part 4: Main Picture - Map-Reduce Mode

#### Main state

```python
class ResearchGraphState(TypedDict):
    topic: str
    max_analysts: int
    human_analyst_feedback: str
    analysts: List[Analyst]
    sections: Annotated[list, operator.add]  # 累积所有章节
    introduction: str
    content: str
    conclusion: str
    final_report: str
```

---

#### initiate_all_interviews - Map steps

```python
def initiate_all_interviews(state: ResearchGraphState):
    human_analyst_feedback = state.get('human_analyst_feedback')

    if human_analyst_feedback:
        return "create_analysts"  # 返回修改分析师

    # 关键：使用 Send() API 并行启动多个子图
    else:
        topic = state["topic"]
        return [
            Send("conduct_interview", {
                "analyst": analyst,
                "messages": [HumanMessage(
                    content=f"So you said you were writing an article on {topic}?"
                )]
            })
            for analyst in state["analysts"]
        ]
```

**The magic of the Send() API**:
- Create a separate instance of the interview subgraph for each analyst
- All interviews **executed in parallel**
- The `sections` output of each subgraph is automatically merged into the main state

**Analogy**:
- Just like a manager sending multiple employees to different locations for research at the same time
- Each employee works independently and reports the results at the end
- Manager consolidates all reports

#### Reduce steps

**1. write_report - Integrate chapters**

```python
def write_report(state: ResearchGraphState):
    sections = state["sections"]  # 包含所有分析师的章节
    topic = state["topic"]

    # 将所有章节合并成一个字符串
    formatted_str_sections = "\n\n".join([f"{section}" for section in sections])

    # LLM 整合成连贯的报告主体
    system_message = report_writer_instructions.format(
        topic=topic,
        context=formatted_str_sections
    )

    report = llm.invoke([
        SystemMessage(content=system_message),
        HumanMessage(content="Write a report based upon these memos.")
    ])

    return {"content": report.content}
```

**2. write_introduction / write_conclusion**

```python
def write_introduction(state: ResearchGraphState):
    sections = state["sections"]
    formatted_str_sections = "\n\n".join([f"{section}" for section in sections])

    instructions = intro_conclusion_instructions.format(
        topic=topic,
        formatted_str_sections=formatted_str_sections
    )

    intro = llm.invoke([instructions, HumanMessage(content="Write the report introduction")])

    return {"introduction": intro.content}
```

---

**3. finalize_report - Assemble final report**

```python
def finalize_report(state: ResearchGraphState):
    content = state["content"]

    # 清理和分离来源部分
    if content.startswith("## Insights"):
        content = content.strip("## Insights")

    if "## Sources" in content:
        content, sources = content.split("\n## Sources\n")

    # 组装完整报告
    final_report = (
        state["introduction"] + "\n\n---\n\n" +
        content + "\n\n---\n\n" +
        state["conclusion"]
    )

    if sources:
        final_report += "\n\n## Sources\n" + sources

    return {"final_report": final_report}
```

## 🔑 Core technology analysis

### 1. Human-in-the-Loop

**Implementation**:
```python
graph = builder.compile(interrupt_before=['human_feedback'], checkpointer=memory)
```

**Workflow**:
1. The graph execution is paused before reaching `human_feedback`
2. The user modifies the status through `graph.update_state()`
3. Continue to execute `graph.stream(None, thread)`

**Practical Application**:
```python
# 第一次运行
for event in graph.stream(initial_input, thread):
    pass  # 在 human_feedback 前停止

# 用户审核并反馈
graph.update_state(thread, {
    "human_analyst_feedback": "Add a startup CEO"
}, as_node="human_feedback")

# 继续运行
for event in graph.stream(None, thread):
    pass  # 重新生成分析师
```

### 2. Send() API - Dynamic Parallelism

**Traditional way vs Send()**:

Traditional way (static):
```python
builder.add_edge("node_a", "node_b")
builder.add_edge("node_a", "node_c")
# 必须预先知道有多少个节点
```

Send() method (dynamic):
```python
def dynamic_dispatch(state):
    return [
        Send("subgraph", {"input": item})
        for item in state["items"]  # 数量在运行时确定
    ]

builder.add_conditional_edges("dispatcher", dynamic_dispatch)
```

**This case application**:
- Number of analysts determined by user input and LLM
- Each analyst corresponds to an independent instance of the interview subgraph
- All interviews run simultaneously, greatly improving efficiency

## 💡 Best Practices and Tips

### 1. Control LLM output format

**Issue**: LLM output format is unstable

**Solution**:
```python
# 定义严格的 Pydantic 模型
class Output(BaseModel):
    field1: str = Field(description="详细描述")
    field2: int

# 强制结构化输出

result = structured_llm.invoke(prompt)  # 保证符合 Output 格式
```

### 2. Loop control

**Problem**: The dialogue may loop infinitely

**Solution**:
```python
def route_messages(state):
    max_turns = state.get('max_num_turns', 2)
    current_turns = count_turns(state['messages'])

    if current_turns >= max_turns:
        return 'end_node'

    if detect_end_signal(state['messages']):
        return 'end_node'

    return 'continue_node'
```

### 3. Merge the results of parallel nodes

**Using Annotated**:
```python
from typing import Annotated
import operator

class State(TypedDict):
    results: Annotated[list, operator.add]  # 自动追加
```

**Effect**:
- Node A returns `{"results": [1, 2]}`
- Node B returns `{"results": [3, 4]}`
- Final state: `{"results": [1, 2, 3, 4]}`

## 🎤 In-depth understanding: the core role of the Interview subgraph in the system

**Interview sub-picture** is the "heart" of the entire research assistant system, which is responsible for the most critical knowledge acquisition task. From a system architecture perspective, it plays three roles:

First, it is the engine of knowledge production. By simulating the "analyst-expert" dialogue mode, the Interview subgraph transforms abstract research topics into concrete and in-depth knowledge content. This multi-round dialogue mechanism (ask_question → search → answer → ask_question) realizes progressive knowledge mining. Each round of dialogue builds on the previous round and ultimately forms valuable research chapters.

Secondly, it is the basic unit of parallelization architecture. Through the `Send()` API, the system can start multiple Interview instances at the same time, and each instance runs independently without interfering with each other. This design allowed interviews with the 3 analysts to be completed within the same time frame rather than being performed serially. The state-isolated nature of subgraphs ensures that each analyst has an independent conversation history and context, avoiding information confusion.

Finally, it is a Map phase implementation of the Map-Reduce pattern. Each Interview subgraph receives an analyst as input and outputs a structured research section. These chapters are automatically aggregated into the main graph state through `Annotated[list, operator.add]`, providing raw materials for the subsequent Reduce stages (write_report, write_introduction, write_conclusion). This clear input and output interface allows subgraphs to be seamlessly integrated into larger systems.

From a technical implementation point of view, the Interview subgraph also shows several important modes of LangGraph: **RAG retrieval enhancement** (providing factual basis for answers through search_web and search_wikipedia), **loop control** (preventing infinite conversations through route_messages), **message role management** (distinguishing the speeches of analysts and experts). The combination of these modes makes Interview not just a simple question and answer process, but a complete, controllable, and high-quality knowledge production pipeline.

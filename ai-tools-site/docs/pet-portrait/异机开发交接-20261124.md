```sh
git pull --ff-only origin main
cd ai-tools-site
npm ci
npm test
npm run pet-portrait:check
```

使用 Node 24（项目固定 24.22.2）及 npm 11.19.1。密钥不在 Git 中；另一台电脑需要自行同步受信任的 `.env.local`，或从 Vercel 拉取获授权环境。不要把密钥发到聊天或提交仓库。

## 当前缺少的配置与验证

1. **SUPABASE_SERVICE_ROLE_KEY**：本地和 Vercel 均缺少。本机 Supabase CLI 返回 `Access token not provided`，插件虽已登录，但提供的接口只支持读取 publishable keys，无法代填此服务端密钥。在 Supabase 项目设置取得后，仅保存到本地和 Vercel production 的服务端环境变量。
2. 用 `npm run pet-portrait:check -- --remote` 运行只读预检。不会调用生成、Stripe 或邮件。缺少配置时返回非零状态，便于区分“代码完成”和“服务可运行”。
3. 密钥齐全后，将 Vercel `PET_PORTRAIT_ENABLED` 设为 true 并部署；先验证图库、上传和一个授权样本的完整任务流程，再启用调度器。
4. 调度器激活：在 Supabase SQL 编辑器运行以下 SQL。若站点域名改变，先更新 Vault 的 `portrait_scheduler_origin`，始终只填 HTTPS 源站，不填路径。

```sql
begin;
select vault.update_secret(id, 'true')
from vault.secrets where name='portrait_scheduler_enabled';
select cron.alter_job(jobid, active := true)
from cron.job where jobname in ('portrait-worker','portrait-cleanup');
commit;
```

暂停时将上述 true 改为 false（包括 Cron active）。不要让缺配置的任务持续空跑。

5. 验证调度：检查 `cron.job_run_details`，并检查 `net._http_response` 的状态码/超时；Cron SQL 成功只说明 HTTP 请求已排入队列，不说明生成完成。HTTP 响应默认仅保留约 6 小时，最终任务状态以 `pet_portrait_jobs` 为准。
6. Stripe 注册后补 `STRIPE_SECRET_KEY`、`STRIPE_PORTRAIT_WEBHOOK_SECRET`，绑定 `/api/pet-portrait/webhook`，在测试模式完成付款、取消、重复通知、退款联调，再切正式密钥。当前不收款。
7. 浏览器视觉及交互验收未完成：内置浏览器组件签名错误，Chrome 连接主机也不可用；本轮仅确认本地风格页、照片页 HTTP 200，未授权 worker 返回 401，不能当作浏览器端到端测试。
8. 出图质量尚未验收：没有适合本业务的授权参考照片，本轮没有付费生成。`风格验收台账.csv` 覆盖 115 项，标出首批 15 项候选；每项需不同人物及宠物样本，不应把配置数量作为已验证效果数量。

网络扩展迁移只在 pg_net 新建且队列/响应为空时重装扩展，无 CASCADE；如已有请求，它会拒绝执行，需先人工核查。
